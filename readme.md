## 项目简介

本项目是一个基于 Linux 系统编程与网络编程实现的 HTTP 静态文件服务器实验项目，核心目标是对比不同并发模型下 Web 服务器的实现方式与性能特征。项目中包含三个版本：`epoll+sendfile`、`multiprocess`、`multithread`，分别展示了基于事件驱动+零拷贝文件传输、多进程、多线程的实现思路。

与传统单机静态站点不同，本项目更偏向于底层网络编程与服务器架构实验，重点关注 socket 监听、请求解析、静态资源响应、并发连接处理以及文件发送优化等方面的实现细节。

## 功能概览

### 通用功能
- 处理 HTTP GET 请求
- 提供静态文件访问服务
- 自动识别常见 MIME 类型
- 支持目录浏览与文件列表展示
- 提供 403、404、413、500 等错误响应
- 使用 `www` 目录作为静态资源根目录
- 支持默认首页访问（如 `index.html`）

### 不同版本的特点

**epoll 版本**：
- 基于 `epoll` 事件驱动模型处理多个连接
- 适合高并发场景下的连接管理
- 通过线程处理已就绪的客户端请求
- 使用 `sendfile()` 将文件内容直接发送到 socket
- 降低用户态和内核态之间的数据复制开销

**multiprocess 版本**：
- 使用 `fork` 创建子进程处理客户端连接
- 通过多进程方式实现并发请求处理
- 适合演示进程模型的服务器设计

**multithread 版本**：
- 使用 POSIX 线程处理客户端请求
- 每个连接可分配独立线程
- 适合对比进程与线程并发模型差异


## 技术栈

| 技术领域 | 核心技术 | 应用场景 |
|----------|----------|----------|
| 网络通信 | Linux Socket | TCP 连接监听与数据收发 |
| 并发模型 | epoll | 高并发事件驱动处理 |
| 并发模型 | fork | 多进程请求并发 |
| 并发模型 | pthread | 多线程请求并发 |

| 资源类型 | MIME 类型识别 | 动态设置 `Content-Type` |

## 核心技术亮点

### 1. epoll 事件驱动模型

`epoll` 是 Linux 下高性能 I/O 多路复用机制之一，适合处理大量并发连接。在本项目中，`http_server_epoll` 版本通过 `epoll_create1()`、`epoll_ctl()` 和 `epoll_wait()` 维护监听集合，并在客户端事件就绪时集中处理连接，可用于展示事件驱动服务器的典型结构。结合使用使用 `sendfile()` 直接从文件描述符向 socket 发送数据，减少传统 `read()` + `write()` 模式中额外的用户态缓存与拷贝成本。这种实现方式非常适合静态资源服务，如 HTML、CSS、JS、图片和文本文件等。

### 2. 多进程与多线程并发设计

项目中的 `http_server_multiprocess` 与 `http_server_multithread` 版本分别体现了两种常见并发思路：
- 多进程：适合对比 `fork()` 创建独立工作进程的处理方式
- 多线程：适合对比线程模型下的请求处理方式

两者共同点都是在客户端连接建立后进行独立处理，以提高同一时刻的服务并发能力。


### 4. 静态资源服务与 HTTP 响应构建

所有版本都具备基础的 HTTP 静态资源服务能力：
- 解析请求路径
- 读取 `www` 目录中的资源
- 识别 `index.html` 与目录访问
- 构造响应头和状态码
- 返回对应内容类型与长度

这一部分体现了典型 Web 服务器的最小工作单元，是整个项目的基础知识结构。

## 安装与运行

### 1. 编译项目

以 epoll 版本为例：

```bash
cd http_server_epoll
make
./server
```

### 2. 访问服务

默认端口配置为 `8080`，可在浏览器中访问：

```text
http://127.0.0.1:8080/
```

访问时会从对应版本下的 `www` 目录读取静态资源，例如：
- `index.html`
- `about.html`
- `style.css`
- `api/test.json`
- 图片资源等

## 运行效果

启动服务后，可通过浏览器访问站点首页，展示类似静态网页资源的内容。同时，项目中的不同版本可用于比较以下维度：
- 事件驱动 vs 多进程 vs 多线程
- 普通文件读取 vs `sendfile()` 优化
- 并发连接处理能力差异
- 静态资源请求与响应流程的实现方式

## 开发环境

- Linux / Unix-like 系统
- GCC

## 适用场景

本项目适合用于：
- 学习 Linux 网络编程基础
- 理解 epoll、多线程和多进程服务器模型
- 研究静态文件 HTTP 服务架构
- 对比不同并发模式下的服务器实现
- 探索 `sendfile()` 在 Web 服务中的应用

## 结语

这个项目的价值不在于实现一个复杂的大型 Web 框架，而在于通过多个小型版本完整展示 Linux 下常见服务器编程方法的基本思路。通过比较不同并发模型与文件传输方式，读者可以更清晰地理解 socket 编程、事件驱动、线程/进程模型以及高性能静态文件传输的核心设计理念。
