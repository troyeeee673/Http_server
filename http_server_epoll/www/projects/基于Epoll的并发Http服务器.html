基于 Linux 系统编程与网络编程实现的 HTTP 静态文件服务器实验项目，对比 epoll 事件驱动、多进程与多线程三种并发模型。

项目简介

本项目是一个基于 Linux 系统编程与网络编程 实现的 HTTP 静态文件服务器实验项目，核心目标是对比不同并发模型下 Web 服务器的实现方式与性能特征。项目中包含三个版本：epoll+sendfile、multiprocess、multithread，分别展示了基于事件驱动 + 零拷贝文件传输、多进程、多线程的实现思路。

与传统单机静态站点不同，本项目更偏向于底层网络编程与服务器架构实验，重点关注 socket 监听、请求解析、静态资源响应、并发连接处理以及文件发送优化等方面的实现细节。

功能概览

通用功能

  • 处理 HTTP GET 请求
  • 提供静态文件访问服务
  • 自动识别常见 MIME 类型
  • 支持目录浏览与文件列表展示
  • 提供 403、404、413、500 等错误响应
  • 使用 www 目录作为静态资源根目录
  • 支持默认首页访问（如 index.html）

不同版本的特点

epoll 版本：

  • 基于 epoll 事件驱动模型处理多个连接
  • 适合高并发场景下的连接管理
  • 通过线程处理已就绪的客户端请求
  • 使用 sendfile() 将文件内容直接发送到 socket
  • 降低用户态和内核态之间的数据复制开销

multiprocess 版本：

  • 使用 fork 创建子进程处理客户端连接
  • 通过多进程方式实现并发请求处理
  • 适合演示进程模型的服务器设计

multithread 版本：

  • 使用 POSIX 线程处理客户端请求
  • 每个连接可分配独立线程
  • 适合对比进程与线程并发模型差异

核心技术亮点

1. epoll 事件驱动模型

epoll 是 Linux 下高性能 I/O 多路复用机制之一，适合处理大量并发连接。在本项目中，http_server_epoll 版本通过 epoll_create1()、epoll_ctl() 和 epoll_wait() 维护监听集合，并在客户端事件就绪时集中处理连接，可用于展示事件驱动服务器的典型结构。

结合使用 sendfile() 直接从文件描述符向 socket 发送数据，减少传统 read() + write() 模式中额外的用户态缓存与拷贝成本。这种实现方式非常适合静态资源服务，如 HTML、CSS、JS、图片和文本文件等。

2. 多进程与多线程并发设计

项目中的 http_server_multiprocess 与 http_server_multithread 版本分别体现了两种常见并发思路：

  • 多进程：适合对比 fork() 创建独立工作进程的处理方式
  • 多线程：适合对比线程模型下的请求处理方式

两者共同点都是在客户端连接建立后进行独立处理，以提高同一时刻的服务并发能力。

3. 静态资源服务与 HTTP 响应构建

所有版本都具备基础的 HTTP 静态资源服务能力：

  • 解析请求路径
  • 读取 www 目录中的资源
  • 识别 index.html 与目录访问
  • 构造响应头和状态码
  • 返回对应内容类型与长度

运行

epoll 版本

# 编译
make epoll

# 启动服务器
./bin/http_server_epoll -p 8080 -r ./www

参数说明：

  • -p 指定端口（默认 8080）
  • -r 指定静态资源根目录（默认 ./www）

multiprocess 版本

# 编译
make multiprocess

# 启动服务器
./bin/http_server_multiprocess -p 8080 -r ./www

multithread 版本

# 编译
make multithread

# 启动服务器
./bin/http_server_multithread -p 8080 -r ./www
