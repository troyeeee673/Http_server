基于Linux系统编程实现的多频道流媒体广播系统，支持IPv6多播、守护进程、多线程并发和令牌桶流量控制。

项目简介

本项目是一个基于Linux系统编程和网络编程实现的多频道流媒体广播系统，采用客户端-服务器架构，通过IPv6多播技术实现音频流的高效分发。系统支持多个频道同时广播，客户端可实时接收节目单并选择收听指定频道。

功能

服务端：

  • 多频道并发广播（最多100个频道，每频道独立线程）
  • 节目单自动扫描与定时推送（每秒广播）
  • 令牌桶流量控制（适配MP3码率，防止网络拥塞）
  • 守护进程模式（支持前后台运行）
  • 优雅退出机制（信号捕获+资源清理）

客户端：

  • 节目单接收与频道选择
  • 数据转发至播放器（管道+进程间通信）
  • 通过 execl 调用 mpg123 播放器解析音频，进行播放

核心技术亮点

1. IPv6多播通信

系统使用IPv6多播地址实现高效的一对多数据分发，相比单播节省带宽资源。服务端加入多播组后，所有数据通过单个socket发送到多播地址，网络层自动复制给所有订阅客户端。

2. 令牌桶流量控制

自定义实现令牌桶算法，精确控制MP3数据发送速率（64kbps），确保客户端播放流畅。使用独立定时器线程每秒为所有令牌桶补充令牌，发送数据时先获取令牌，令牌不足时阻塞等待。

关键设计：

  • cps：每秒补充64K令牌（匹配MP3码率）
  • burst：令牌桶容量640K（10秒缓冲）
  • 条件变量唤醒机制，避免忙等待

3. 多线程并发架构

每个频道创建独立线程，节目单线程与频道线程分离：

  • 节目单线程：每秒广播一次节目单信息
  • 频道线程：持续读取媒体文件并发送多播数据

使用 sched_yield() 主动出让CPU时间片，避免单个线程占用过多资源。

4. 守护进程模式

完整的守护进程化实现：

  • fork() 创建子进程，父进程退出
  • setsid() 创建新会话，脱离终端
  • dup2() 重定向标准输入/输出/错误到 /dev/null
  • chdir("/") 切换工作目录
  • umask(0) 重置文件权限掩码

运行

服务端

# 前台运行（调试模式）
./src/server/server -F -D /path/to/media

# 后台守护进程运行
./src/server/server -D /path/to/media

参数说明：

  • -M 指定多播组
  • -P 指定端口
  • -F 前台运行
  • -D 指定媒体目录

客户端

./src/client/client

参数说明：

  • -M / --mgroup 指定多播组
  • -P / --port 指定接收端口
  • -p / --player 指定播放器
  • -H / --help 显示帮助
